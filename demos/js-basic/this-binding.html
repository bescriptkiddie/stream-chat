this 指向与绑定规则

深入理解 JavaScript 中的 this，手写 call/apply/bind

📚 this 的四种绑定规则

1️⃣

默认绑定

独立函数调用，this 指向全局对象

function foo() {
  console.log(this); // window
}
foo();

严格模式下是 undefined

2️⃣

隐式绑定

对象方法调用，this 指向对象

const obj = {
  name: 'Alice',
  greet() {
    console.log(this.name);
  }
};
obj.greet(); // 'Alice'

⚠️ 赋值给变量会丢失绑定

3️⃣

显式绑定

call/apply/bind 显式指定 this

function greet() {
  console.log(this.name);
}
const obj = { name: 'Bob' };
greet.call(obj); // 'Bob'

✅ 优先级高于隐式绑定

4️⃣

new 绑定

构造函数调用，this 指向新对象

function Person(name) {
  this.name = name;
}
const p = new Person('Charlie');
console.log(p.name); // 'Charlie'

✅ 优先级最高

🎯 优先级顺序：new 绑定 > 显式绑定 > 隐式绑定 > 默认绑定

💻 手写 call/apply/bind

点击查看完整实现

手写 call:

Function.prototype.myCall = function(context, ...args) {
  // 1. 处理 null/undefined，指向 window
  context = context || window;
  
  // 2. 将函数设为对象的属性（使用 Symbol 避免覆盖）
  const fnSymbol = Symbol();
  context[fnSymbol] = this;
  
  // 3. 执行函数
  const result = context[fnSymbol](...args);
  
  // 4. 删除临时属性
  delete context[fnSymbol];
  
  return result;
};

手写 apply:

Function.prototype.myApply = function(context, argsArray) {
  context = context || window;
  const fnSymbol = Symbol();
  context[fnSymbol] = this;
  
  // 与 call 的唯一区别：参数是数组
  const result = argsArray 
    ? context[fnSymbol](...argsArray)
    : context[fnSymbol]();
  
  delete context[fnSymbol];
  return result;
};

手写 bind:

Function.prototype.myBind = function(context, ...args) {
  const fn = this;
  
  // bind 返回一个新函数
  return function(...newArgs) {
    // 判断是否用 new 调用
    if (this instanceof fn) {
      // new 调用：this 指向新对象
      return new fn(...args, ...newArgs);
    }
    
    // 普通调用：使用绑定的 context
    return fn.apply(context, [...args, ...newArgs]);
  };
};

🔑 核心要点总结

1. 判断 this 的流程

  1. 是否用 new 调用？→ this 指向新对象
  2. 是否用 call/apply/bind？→ this 指向传入的对象
  3. 是否是对象方法？→ this 指向该对象
  4. 默认情况 → this 指向 window (严格模式 undefined)

2. 箭头函数特殊规则

  • 没有自己的 this，继承外层作用域的 this
  • 不能用 call/apply/bind 改变 this
  • 不能用 new 调用（没有 constructor）
  • 适用场景：回调函数、需要继承外层 this 的地方

3. call vs apply vs bind

方法参数返回值执行时机
call逐个传参函数执行结果立即执行
apply数组传参函数执行结果立即执行
bind逐个传参新函数返回函数，延迟执行

🎤 面试场景模拟

👔
面试官：下面代码输出什么？
const obj = {
  name: 'Alice',
  greet: function() {
    console.log(this.name);
  }
};

const greet = obj.greet;
greet();
setTimeout(obj.greet, 1000);
[obj.greet].forEach(fn => fn());
✅ 正确答案：
  • greet(): undefined（隐式绑定丢失）
  • setTimeout(obj.greet, 1000): undefined（传参时丢失绑定）
  • [obj.greet].forEach(...): undefined（回调函数丢失绑定）

💡 解决方法：使用箭头函数或 bind

setTimeout(() => obj.greet(), 1000);  // 'Alice'
setTimeout(obj.greet.bind(obj), 1000); // 'Alice'
👔
面试官：手写一个 call 方法
✅ 实现思路：

核心原理：将函数作为对象的方法调用

  1. 将函数设为 context 的属性
  2. 执行该方法（this 自动指向 context）
  3. 删除临时属性
  4. 返回结果

💡 关键点：用 Symbol 避免属性名冲突

👔
面试官：箭头函数的 this 和普通函数有什么区别？
✅ 好的回答：

普通函数

  • this 在调用时确定
  • 可被 call/apply/bind 改变
  • 可用 new 调用
  • 有 arguments 对象

箭头函数

  • this 在定义时确定
  • 不可改变 this
  • 不可用 new 调用
  • 没有 arguments

💡 使用场景：需要继承外层 this 时用箭头函数，需要动态 this 时用普通函数

👔
面试官：bind 返回的函数可以用 new 调用吗？
function Person(name) {
  this.name = name;
}

const obj = { name: 'Object' };
const BoundPerson = Person.bind(obj);
const instance = new BoundPerson('Instance');

console.log(instance.name); // ?
✅ 正确答案：'Instance'

关键点：

  • bind 返回的函数可以用 new 调用
  • new 调用时，bind 的 this 绑定会被忽略
  • this 指向新创建的对象 (instance)
  • 这是 bind 的特殊行为，需要在实现中处理
// myBind 实现中的关键代码
return function(...newArgs) {
  if (this instanceof fn) {
    // new 调用：忽略 bind 的 context
    return new fn(...args, ...newArgs);
  }
  return fn.apply(context, [...args, ...newArgs]);
};

❓ 面试高频 QA

Q1: React 中的 this 绑定问题

类组件中的事件处理器：

class MyComponent extends React.Component {
  handleClick() {
    console.log(this); // undefined!
  }

  render() {
    return <button onClick={this.handleClick}>Click</button>;
  }
}

// 解决方法 1: 箭头函数
<button onClick={() => this.handleClick()}>Click</button>

// 解决方法 2: bind
constructor() {
  this.handleClick = this.handleClick.bind(this);
}

// 解决方法 3: 类字段 (推荐)
handleClick = () => {
  console.log(this); // 组件实例
};
Q2: call 和 apply 的性能差异

结论：现代浏览器中几乎没有差异

  • 早期：apply 需要展开数组，性能略差
  • 现代：JS 引擎优化，性能差异可忽略
  • 选择标准：根据参数形式选择，不必纠结性能

💡 使用建议：参数明确用 call，参数是数组用 apply

Q3: 如何让 setTimeout 中的 this 指向特定对象？

四种方法：

方法 1: 箭头函数（推荐）

setTimeout(() => {
  console.log(this.name);
}, 1000);

方法 2: bind

setTimeout(function() {
  console.log(this.name);
}.bind(this), 1000);

方法 3: 闭包保存 this

const self = this;
setTimeout(function() {
  console.log(self.name);
}, 1000);
Q4: 阶跃星辰 AI 产品中，this 会有哪些应用场景？

常见场景：

  1. 事件处理器绑定
    class ChatPanel {
  handleSend = () => {
    // 箭头函数自动绑定 this
    this.sendMessage();
  };
}
  2. API 请求回调
    fetchMessages().then(data => {
  // 箭头函数继承外层 this
  this.setState({ messages: data });
});
  3. 流式响应处理
    reader.read().then(function process({ done, value }) {
  if (done) return;
  // 需要 bind 或箭头函数保持 this
  this.appendMessage(value);
  return reader.read().then(process.bind(this));
}.bind(this));

🔥 可能的追问

追问 1：严格模式对 this 有什么影响？

→ 默认绑定时 this 是 undefined 而不是 window

追问 2：为什么不推荐在构造函数中使用箭头函数定义方法？

→ 每个实例都会创建新函数，浪费内存；应该定义在原型上

追问 3：eval 中的 this 指向什么？

→ 继承外层作用域的 this

追问 4：Object.create(null) 创建的对象能用 call 绑定吗？

→ 可以，this 会指向该对象
