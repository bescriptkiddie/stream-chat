闭包演示 (Closure)

JavaScript 闭包原理与实际应用场景

📚 什么是闭包？

简单定义：函数 + 函数能访问的外部变量 = 闭包

当内部函数引用了外部函数的变量时，即使外部函数执行完毕，这些变量也不会被销毁，内部函数依然可以访问。

场景 1: 计数器（私有变量）

function createCounter() {
  let count = 0; // 私有变量，外部无法访问
  
  return {
    increment: () => ++count,
    decrement: () => --count,
    getCount: () => count
  };
}

const counter1 = createCounter();
counter1.increment(); // 1
counter1.increment(); // 2

const counter2 = createCounter();
counter2.increment(); // 1 (独立的闭包)
💡 每个计数器都有自己独立的 count 变量，互不干扰

场景 2: 循环中的闭包陷阱 ⚠️（高频面试题）

❌ 错误写法 (var):
for (var i = 0; i < 5; i++) {
  setTimeout(() => {
    console.log(i); // 全部输出 5
  }, 100);
}
// 原因: var 是函数作用域，i 被共享
✅ 正确写法 1 (let):
for (let i = 0; i < 5; i++) {
  setTimeout(() => {
    console.log(i); // 输出 0, 1, 2, 3, 4
  }, 100);
}
// 原因: let 是块级作用域，每次循环创建新的 i
✅ 正确写法 2 (立即执行函数):
for (var i = 0; i < 5; i++) {
  (function(index) {
    setTimeout(() => {
      console.log(index); // 输出 0, 1, 2, 3, 4
    }, 100);
  })(i);
}
// 原因: IIFE 创建闭包，捕获每次的 i 值

🎤 面试场景模拟

👔
面试官：能用一句话解释什么是闭包吗？
✅ 好的回答：

"闭包就是函数加上它能访问的外部变量"

更准确地说：当一个内部函数引用了外部函数的变量时，即使外部函数执行完毕，这些变量也不会被销毁，内部函数依然可以访问它们，这就形成了闭包。

举个例子：

function outer() {
  let count = 0;  // 外部变量
  return function inner() {
    count++;      // 内部函数引用外部变量
    return count;
  };
}
const counter = outer();
counter(); // 1  ← 闭包让 count 一直存活
counter(); // 2
❌ 差的回答：
"闭包就是函数里面套函数"（不准确，嵌套函数不一定是闭包）
👔
面试官：下面代码会输出什么？
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 1000);
}
// 输出什么？
✅ 好的回答：

输出：3 3 3

原因分析：

  1. var 是函数作用域，整个循环只有一个 i
  2. setTimeout 是异步的，回调函数会在循环结束后才执行
  3. 执行时 i 已经变成 3，所以三次都输出 3

解决方法：

方法 1：改用 let
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
// 输出 0 1 2 (let 是块级作用域)
方法 2：立即执行函数（IIFE）
for (var i = 0; i < 3; i++) {
  (function(j) {
    setTimeout(() => console.log(j), 1000);
  })(i);
}
// 输出 0 1 2 (IIFE 创建新作用域)
👔
面试官：闭包会造成内存泄漏吗？怎么避免？
✅ 好的回答：

闭包本身不会造成内存泄漏，但使用不当会导致

❌ 容易泄漏的场景：

function createHandler() {
  const largeData = new Array(1000000);
  
  return function() {
    console.log(largeData.length); // 持续引用大对象
  };
}

const handler = createHandler();
// largeData 永远不会被释放，导致内存泄漏

✅ 避免泄漏的方法：

  1. 及时解除引用：
    2. let handler = createHandler();
// 使用完后
handler = null; // 解除引用，允许垃圾回收
  2. 只保留必要的变量：
    3. function createHandler() {
  const largeData = new Array(1000000);
  const length = largeData.length; // 只保留需要的
  
  return function() {
    console.log(length); // 不引用整个 largeData
  };
}
  3. 使用 WeakMap 存储大对象：弱引用不会阻止垃圾回收
👔
面试官：实际项目中闭包有哪些应用场景？
✅ 好的回答：

1. 防抖节流（最常见）

function debounce(fn, delay) {
  let timer = null; // 闭包变量
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

2. 模块化封装（私有方法）

const userModule = (() => {
  const users = []; // 私有数据
  
  return {
    addUser: (user) => users.push(user),
    getUsers: () => [...users] // 返回副本
  };
})();

3. 柯里化（函数式编程）

function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn(...args);
    }
    return (...moreArgs) => curried(...args, ...moreArgs);
  };
}

const add = (a, b, c) => a + b + c;
const curriedAdd = curry(add);
curriedAdd(1)(2)(3); // 6

4. React Hooks 内部实现

function useState(initialValue) {
  let state = initialValue; // 闭包保存状态
  
  function setState(newValue) {
    state = newValue;
    render(); // 触发重新渲染
  }
  
  return [state, setState];
}

❓ 面试高频 QA

Q1: 闭包和作用域链是什么关系？

闭包是作用域链的应用：

  • 作用域链：当前作用域 → 外层作用域 → 全局作用域
  • 闭包保存了函数定义时的整个作用域链
  • 即使外层函数执行完毕，作用域链仍然保留
let global = 'global';

function outer() {
  let outerVar = 'outer';
  
  function inner() {
    let innerVar = 'inner';
    console.log(innerVar);  // 当前作用域
    console.log(outerVar);  // 外层作用域（闭包）
    console.log(global);    // 全局作用域
  }
  return inner;
}

const fn = outer(); // inner 的作用域链被保留
Q2: 箭头函数会形成闭包吗？

会！箭头函数也能形成闭包

function outer() {
  let count = 0;
  
  // 箭头函数形成闭包
  return () => ++count;
}

const counter = outer();
counter(); // 1
counter(); // 2

区别：

  • 箭头函数没有自己的 this，会继承外层的 this
  • 这也是一种闭包行为（捕获外层的 this）
Q3: 如何检测是否存在内存泄漏？

使用 Chrome DevTools：

  1. 打开 Performance 标签，录制内存快照
  2. 重复操作，观察内存是否持续增长
  3. 使用 Memory 标签查看堆快照（Heap Snapshot）
  4. 对比不同时间点的快照，查找未释放的对象

代码层面检测：

// 记录对象创建
const activeHandlers = new Set();

function createHandler() {
  const handler = () => {};
  activeHandlers.add(handler);
  return handler;
}

// 定期检查
setInterval(() => {
  console.log('Active handlers:', activeHandlers.size);
}, 5000);
Q4: 闭包的性能影响大吗？

性能影响很小，不必过度担心

✅ 可以放心使用的场景：

  • 事件处理函数（数量有限）
  • 防抖节流（每个函数只创建一个闭包）
  • React Hooks（框架层面优化）
  • 模块化封装（单例模式）

⚠️ 需要注意的场景：

  • 循环中大量创建闭包（优先用 let）
  • 闭包引用大对象（WeakMap 优化）
  • 长期保留的闭包未清理（及时解除引用）

💡 建议：先写清晰的代码，遇到性能问题再优化。
