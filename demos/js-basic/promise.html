Promise 原理与手写实现

深入理解 Promise A+ 规范，手写完整实现

📚 Promise 核心概念

⏳
Pending
初始状态
✅
Fulfilled
成功状态
❌
Rejected
失败状态

状态转换规则

  • • Pending → Fulfilled: 调用 resolve(value)
  • • Pending → Rejected: 调用 reject(reason)
  • • 状态一旦改变，不可逆转
  • • Fulfilled 和 Rejected 互不转换

💻 核心代码实现

class MyPromise {
  constructor(executor) {
    this.state = 'pending';
    this.value = undefined;
    this.reason = undefined;
    this.onFulfilledCallbacks = [];
    this.onRejectedCallbacks = [];

    const resolve = (value) => {
      if (this.state === 'pending') {
        this.state = 'fulfilled';
        this.value = value;
        this.onFulfilledCallbacks.forEach(fn => fn());
      }
    };

    const reject = (reason) => {
      if (this.state === 'pending') {
        this.state = 'rejected';
        this.reason = reason;
        this.onRejectedCallbacks.forEach(fn => fn());
      }
    };

    try {
      executor(resolve, reject);
    } catch (error) {
      reject(error);
    }
  }

  then(onFulfilled, onRejected) {
    onFulfilled = typeof onFulfilled === 'function' 
      ? onFulfilled 
      : value => value;
    onRejected = typeof onRejected === 'function' 
      ? onRejected 
      : reason => { throw reason };

    const promise2 = new MyPromise((resolve, reject) => {
      if (this.state === 'fulfilled') {
        setTimeout(() => {
          try {
            const x = onFulfilled(this.value);
            resolve(x);
          } catch (error) {
            reject(error);
          }
        }, 0);
      } else if (this.state === 'rejected') {
        setTimeout(() => {
          try {
            const x = onRejected(this.reason);
            resolve(x);
          } catch (error) {
            reject(error);
          }
        }, 0);
      } else if (this.state === 'pending') {
        this.onFulfilledCallbacks.push(() => {
          setTimeout(() => {
            try {
              const x = onFulfilled(this.value);
              resolve(x);
            } catch (error) {
              reject(error);
            }
          }, 0);
        });

        this.onRejectedCallbacks.push(() => {
          setTimeout(() => {
            try {
              const x = onRejected(this.reason);
              resolve(x);
            } catch (error) {
              reject(error);
            }
          }, 0);
        });
      }
    });

    return promise2;
  }

  catch(onRejected) {
    return this.then(null, onRejected);
  }

  static resolve(value) {
    return new MyPromise(resolve => resolve(value));
  }

  static reject(reason) {
    return new MyPromise((resolve, reject) => reject(reason));
  }

  static all(promises) {
    return new MyPromise((resolve, reject) => {
      const results = [];
      let count = 0;

      promises.forEach((promise, index) => {
        MyPromise.resolve(promise).then(
          value => {
            results[index] = value;
            count++;
            if (count === promises.length) {
              resolve(results);
            }
          },
          reject
        );
      });
    });
  }

  static race(promises) {
    return new MyPromise((resolve, reject) => {
      promises.forEach(promise => {
        MyPromise.resolve(promise).then(resolve, reject);
      });
    });
  }
}

🔑 关键实现点

1. 状态管理

  • • 用变量保存状态 (pending/fulfilled/rejected)
  • • 状态只能改变一次（if state === 'pending' 判断）
  • • 保存 value/reason 供后续使用

2. 回调队列

  • • 用数组保存多个 then 的回调
  • • pending 状态时收集回调
  • • resolve/reject 时遍历执行

3. 链式调用

  • • then 返回新的 Promise
  • • 用 setTimeout 实现异步（微任务）
  • • 传递上一个 then 的返回值

4. 错误处理

  • • try-catch 包裹 executor 和回调
  • • catch 方法是 then(null, onRejected) 的语法糖
  • • 错误会沿着 then 链传递

🎤 面试场景模拟

👔
面试官：请手写一个简化版的 Promise
✅ 回答思路：

我会按照 Promise A+ 规范实现，核心包括：

  1. 状态机：pending/fulfilled/rejected 三种状态
  2. executor：接收 resolve/reject 两个参数
  3. then 方法：返回新 Promise，支持链式调用
  4. 回调队列：处理异步场景的多个 then
  5. 错误处理：try-catch + catch 方法

然后边写边讲解每个部分的作用和注意事项

👔
面试官：为什么 then 要用 setTimeout 包裹？
✅ 好的回答：

两个原因：

1. 实现异步（符合规范）

Promise A+ 规范要求 then 的回调必须异步执行，不能同步执行

// 如果同步执行
promise.then(() => console.log('then'));
console.log('sync');
// 输出: then, sync (错误！)

// 异步执行
promise.then(() => console.log('then'));
console.log('sync');
// 输出: sync, then (正确！)

2. 解决 promise2 引用问题

then 返回的新 Promise (promise2) 在创建时还没赋值完成，需要异步才能访问

💡 注意：实际应该用微任务（queueMicrotask），setTimeout 是宏任务

👔
面试官：Promise.all 和 Promise.race 有什么区别？
✅ 好的回答：

Promise.all

  • 等待全部完成
  • 所有成功 → 返回结果数组
  • 任一失败 → 立即 reject
  • 适用：并发请求，需要所有结果
Promise.all([p1, p2, p3])
  .then(results => {
    // [r1, r2, r3]
  });

Promise.race

  • 竞速，最快完成
  • 返回第一个完成的结果
  • 无论成功还是失败
  • 适用：超时控制、缓存竞争
Promise.race([
  fetch('/api'),
  timeout(5000)
])
👔
面试官：下面代码输出什么？（Promise 经典题）
Promise.resolve().then(() => {
  console.log(1);
  return Promise.resolve(2);
}).then(res => {
  console.log(res);
});

Promise.resolve().then(() => {
  console.log(3);
}).then(() => {
  console.log(4);
}).then(() => {
  console.log(5);
});
✅ 正确答案：1 → 3 → 4 → 5 → 2

解析：

  • 第一轮微任务：执行第一个 then (输出 1) 和第二个 Promise 的第一个 then (输出 3)
  • 关键：return Promise.resolve(2) 会产生额外的微任务
  • 第二轮微任务：执行第二个 Promise 的第二个 then (输出 4)
  • 第三轮微任务：执行第二个 Promise 的第三个 then (输出 5)
  • 第四轮微任务：resolve(2) 的回调终于执行 (输出 2)

💡 知识点：then 返回 Promise 会产生额外的微任务（Promise 展开过程）

❓ 面试高频 QA

Q1: Promise 和 async/await 有什么区别？

async/await 是 Promise 的语法糖：

Promise 写法

fetch('/api')
  .then(res => res.json())
  .then(data => {
    console.log(data);
  })
  .catch(err => {
    console.error(err);
  });

async/await 写法

async function getData() {
  try {
    const res = await fetch('/api');
    const data = await res.json();
    console.log(data);
  } catch (err) {
    console.error(err);
  }
}

💡 优势：代码更像同步，更易读；本质：底层还是 Promise

Q2: 如何实现 Promise.allSettled？

与 Promise.all 的区别：所有 Promise 都完成（无论成功失败）才返回

MyPromise.allSettled = function(promises) {
  return new MyPromise(resolve => {
    const results = [];
    let count = 0;

    promises.forEach((promise, index) => {
      MyPromise.resolve(promise).then(
        value => {
          results[index] = { status: 'fulfilled', value };
          count++;
          if (count === promises.length) resolve(results);
        },
        reason => {
          results[index] = { status: 'rejected', reason };
          count++;
          if (count === promises.length) resolve(results);
        }
      );
    });
  });
};

✅ 关键：成功和失败都执行相同逻辑，不提前 reject

Q3: Promise 如何实现超时控制？

使用 Promise.race 实现：

function promiseWithTimeout(promise, timeout) {
  const timeoutPromise = new Promise((resolve, reject) => {
    setTimeout(() => {
      reject(new Error('请求超时'));
    }, timeout);
  });

  return Promise.race([promise, timeoutPromise]);
}

// 使用
promiseWithTimeout(fetch('/api'), 5000)
  .then(data => console.log(data))
  .catch(err => console.error(err)); // 5秒后超时
Q4: 如何实现 Promise 的并发控制？

场景：100 个请求，最多同时发送 5 个

async function promiseLimit(tasks, limit) {
  const results = [];
  const executing = [];

  for (const task of tasks) {
    const p = Promise.resolve().then(() => task());
    results.push(p);

    if (limit <= tasks.length) {
      const e = p.then(() => {
        executing.splice(executing.indexOf(e), 1);
      });
      executing.push(e);

      if (executing.length >= limit) {
        await Promise.race(executing);
      }
    }
  }

  return Promise.all(results);
}

// 使用
const tasks = urls.map(url => () => fetch(url));
promiseLimit(tasks, 5); // 最多同时 5 个请求

💼 实际应用场景

1. 并发请求优化（阶跃星辰 AI 场景）
// 同时获取模型列表和用户信息
Promise.all([
  fetch('/api/models'),
  fetch('/api/user')
]).then(([models, user]) => {
  // 两个请求都完成，渲染页面
});
2. 缓存竞争（优先返回缓存）
Promise.race([
  getFromCache('/api/data'),
  fetch('/api/data')
]).then(data => {
  // 谁快用谁
});
3. 重试机制
function retry(fn, times) {
  return new Promise((resolve, reject) => {
    function attempt() {
      fn().then(resolve).catch(err => {
        if (times-- > 0) {
          setTimeout(attempt, 1000);
        } else {
          reject(err);
        }
      });
    }
    attempt();
  });
}

🔥 可能的追问

追问 1：Promise 链式调用如果中间有错误会怎样？

→ 错误会沿着链传递，直到被 catch 捕获

追问 2：Promise.all 中一个失败了，其他的还会执行吗？

→ 会继续执行，但结果会被忽略（Promise.all 立即 reject）

追问 3：如何取消一个 Promise？

→ Promise 本身不可取消，但可以用 AbortController 取消 fetch 请求

追问 4：finally 的实现原理是什么？

→ 无论成功失败都执行，但不改变 Promise 的值/原因
