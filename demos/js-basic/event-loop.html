事件循环 (Event Loop)

JavaScript 异步编程核心 - 宏任务与微任务的执行顺序

📚 事件循环核心概念

⚡同步任务 (Synchronous)

  • • 立即执行的代码
  • • 在主线程上按顺序执行
  • • 会阻塞后续代码
  • • 例: console.log, 变量声明

🔴宏任务 (Macro Task)

  • • 异步执行的任务
  • • 每次只执行一个宏任务
  • • 执行完后检查微任务
  • • 例: setTimeout, setInterval, I/O

🟢微任务 (Micro Task)

  • • 优先级高于宏任务
  • • 会清空整个微任务队列
  • • 在下一个宏任务前执行
  • • 例: Promise.then, MutationObserver

🔄执行顺序

  1. 执行所有同步代码
  2. 清空微任务队列
  3. 执行一个宏任务
  4. 重复步骤 2-3

场景 1: 基础事件循环（逐步演示）

示例代码

console.log('1: 同步代码开始');

setTimeout(() => {
  console.log('2: setTimeout (宏任务)');
}, 0);

Promise.resolve().then(() => {
  console.log('3: Promise.then (微任务)');
});

console.log('4: 同步代码结束');

执行顺序

点击"开始逐步演示"查看执行过程

💡 正确答案：1 → 4 → 3 → 2

同步代码先执行 (1, 4)，然后清空微任务 (3)，最后执行宏任务 (2)

场景 2: 复杂嵌套（面试高频）⚠️

示例代码

console.log('1: start');

setTimeout(() => {
  console.log('2: setTimeout1');
  Promise.resolve().then(() => {
    console.log('3: Promise in setTimeout1');
  });
}, 0);

Promise.resolve().then(() => {
  console.log('4: Promise1');
  setTimeout(() => {
    console.log('5: setTimeout in Promise1');
  }, 0);
});

Promise.resolve().then(() => {
  console.log('6: Promise2');
});

console.log('7: end');

执行顺序详解

点击按钮查看执行过程

💡 正确答案：1 → 7 → 4 → 6 → 2 → 3 → 5

关键理解：每个宏任务执行后，都要清空微任务队列！

🎯 事件循环核心规则

  1. 同步代码优先：主线程的同步代码最先执行
  2. 微任务优先于宏任务：Promise.then 比 setTimeout 先执行
  3. 清空微任务队列：微任务会一次性全部执行完
  4. 宏任务逐个执行：每次只执行一个宏任务
  5. 循环检查：宏任务 → 微任务 → 宏任务 → 微任务...

📋 常见任务分类表

同步任务

  • • console.log()
  • • 变量声明/赋值
  • • 函数调用
  • • 循环、条件判断

  • • setTimeout()

🎤 面试场景模拟

👔
面试官：请解释一下 JavaScript 的事件循环机制
✅ 好的回答：

JavaScript 是单线程语言，通过事件循环实现异步。核心机制是：

  1. 执行栈：执行所有同步代码
  2. 微任务队列：清空所有微任务（Promise.then）
  3. 宏任务队列：执行一个宏任务（setTimeout）
  4. 循环：重复步骤 2-3，直到所有任务完成

关键点：微任务优先级高于宏任务，每执行一个宏任务后都要清空微任务队列。

❌ 差的回答：
"就是异步任务放到队列里，然后按顺序执行"（太笼统，没有区分宏任务和微任务）
👔
面试官：下面代码输出什么？（经典题）
async function async1() {
  console.log('async1 start');
  await async2();
  console.log('async1 end');
}

async function async2() {
  console.log('async2');
}

console.log('script start');

setTimeout(() => {
  console.log('setTimeout');
}, 0);

async1();

new Promise(resolve => {
  console.log('promise1');
  resolve();
}).then(() => {
  console.log('promise2');
});

console.log('script end');
✅ 正确答案：
script start
async1 start
async2
promise1
script end
async1 end
promise2
setTimeout

解析：

  1. 同步代码：script start → async1 start → async2 → promise1 → script end
  2. 微任务：async1 end (await后的代码) → promise2
  3. 宏任务：setTimeout

💡 关键：await 后面的代码相当于 Promise.then()，是微任务！

👔
面试官：为什么微任务要一次性清空，而宏任务要逐个执行？
✅ 好的回答：

设计目的不同：

微任务（一次性清空）

  • 目的：保证状态一致性
  • 场景：Promise 链式调用需要连续执行
  • 好处：避免中间状态被宏任务打断

宏任务（逐个执行）

  • 目的：避免阻塞渲染
  • 场景：setTimeout、I/O 等耗时操作
  • 好处：每个宏任务后都能渲染 UI，保证响应性

💡 比喻：微任务像"快递员一次送完所有快递"，宏任务像"每送一件快递休息一下"

❓ 面试高频 QA

Q1: Node.js 的事件循环和浏览器有什么区别？

主要区别：

浏览器

  • 微任务：清空队列
  • 宏任务：逐个执行
  • 每个宏任务后可能渲染
  • setTimeout 最小延迟 4ms

Node.js

  • 分为 6 个阶段（timers、I/O等）
  • 每个阶段执行完才检查微任务
  • setImmediate 和 setTimeout 顺序不固定
  • process.nextTick 优先级最高
Q2: requestAnimationFrame 是宏任务还是微任务？

都不是！它是独立的渲染阶段任务

执行顺序：

1. 执行同步代码
2. 清空微任务队列
3. 执行 requestAnimationFrame 回调
4. 渲染 UI
5. 执行宏任务

💡 rAF 在每次浏览器重绘前执行，用于流畅动画（60fps）

Q3: async/await 是如何转换成 Promise 的？

await 会将后续代码放入微任务队列：

async/await 写法

async function foo() {
  console.log('1');
  await bar();
  console.log('2');
}

foo();
console.log('3');

等价的 Promise 写法

function foo() {
  console.log('1');
  return Promise.resolve(bar())
    .then(() => {
      console.log('2');
    });
}

foo();
console.log('3');

输出：1 → 3 → 2

Q4: 如何让宏任务立即执行？

无法！但可以用这些技巧：

  1. 使用 Promise 替代 setTimeout：
    // setTimeout 是宏任务，会等微任务完成
setTimeout(() => console.log('宏任务'), 0);

// Promise.then 是微任务，更快执行
Promise.resolve().then(() => console.log('微任务'));
  2. Node.js 使用 setImmediate：
    setImmediate(() => {
  console.log('比 setTimeout 更快');
});
  3. 关键理解：宏任务必须等微任务清空，这是设计原则，无法绕过

💼 实际应用场景

1. 优化用户体验（分批渲染大量数据）
function renderLargeList(items) {
  const batchSize = 100;
  let index = 0;
  
  function renderBatch() {
    const batch = items.slice(index, index + batchSize);
    batch.forEach(item => renderItem(item));
    index += batchSize;
    
    if (index < items.length) {
      setTimeout(renderBatch, 0); // 分批渲染，不阻塞 UI
    }
  }
  
  renderBatch();
}
2. 确保 DOM 更新后执行（微任务）
element.textContent = 'new value';

Promise.resolve().then(() => {
  // 保证在这次渲染周期内执行，但在 DOM 更新后
  console.log(element.offsetHeight); // 获取最新高度
});
3. 防抖节流原理（宏任务）
function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer); // 取消之前的宏任务
    timer = setTimeout(() => fn(...args), delay); // 创建新的宏任务
  };
}

🔥 可能的追问

追问 1：如果微任务中又创建了新的微任务，会怎样？

→ 新的微任务会加入队列，继续执行，直到队列清空（可能死循环）

追问 2：为什么 setTimeout(fn, 0) 不是立即执行？

→ 因为要等同步代码和微任务执行完，且浏览器有 4ms 最小延迟

追问 3：如何实现一个精准的定时器？

→ 使用 requestAnimationFrame + 时间戳校准，或 Web Worker

追问 4：React 的 setState 是同步还是异步的？

→ 在事件处理中是"异步"（批量更新），在 setTimeout 中是"同步"
