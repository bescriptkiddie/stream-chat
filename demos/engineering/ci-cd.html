🛠️ CI/CD 工具选择

GitHub Actions（推荐）

# .github/workflows/ci.yml
name: CI/CD Pipeline

on:
  push:
    branches: [main, dev]
  pull_request:
    branches: [main]

jobs:
  # ===== Job 1: 代码检查和测试 =====
  test:
    runs-on: ubuntu-latest
    steps:
      - name: 检出代码
        uses: actions/checkout@v3
      
      - name: 设置 Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
          cache: 'pnpm'
      
      - name: 安装 pnpm
        run: npm install -g pnpm
      
      - name: 安装依赖
        run: pnpm install --frozen-lockfile
      
      - name: 代码检查
        run: pnpm run lint
      
      - name: 类型检查
        run: pnpm run type-check
      
      - name: 运行测试
        run: pnpm run test
      
      - name: 生成覆盖率报告
        run: pnpm run test:coverage
      
      - name: 上传覆盖率到 Codecov
        uses: codecov/codecov-action@v3
        with:
          token: ${{ secrets.CODECOV_TOKEN }}

  # ===== Job 2: 构建和部署 =====
  deploy:
    needs: test  # 依赖 test job 成功
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'  # 只在 main 分支部署
    
    steps:
      - name: 检出代码
        uses: actions/checkout@v3
      
      - name: 设置 Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      
      - name: 安装依赖
        run: pnpm install
      
      - name: 构建项目
        run: pnpm run build
        env:
          VITE_API_URL: ${{ secrets.VITE_API_URL }}
      
      - name: 部署到 Vercel
        uses: amondnet/vercel-action@v20
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}
          vercel-args: '--prod'
      
      - name: 通知部署成功
        if: success()
        run: |
          curl -X POST ${{ secrets.SLACK_WEBHOOK }} \
            -H 'Content-Type: application/json' \
            -d '{"text":"🚀 部署成功！"}'

2️⃣ 多环境部署（开发/测试/生产）
# .github/workflows/multi-env.yml
name: Multi-Environment Deploy

on:
  push:
    branches:
      - dev      # 开发环境
      - staging  # 测试环境
      - main     # 生产环境

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Determine environment
        id: env
        run: |
          if [[ ${{ github.ref }} == 'refs/heads/main' ]]; then
            echo "ENV=production" >> $GITHUB_OUTPUT
            echo "API_URL=https://api.stepfun.com" >> $GITHUB_OUTPUT
          elif [[ ${{ github.ref }} == 'refs/heads/staging' ]]; then
            echo "ENV=staging" >> $GITHUB_OUTPUT
            echo "API_URL=https://api-staging.stepfun.com" >> $GITHUB_OUTPUT
          else
            echo "ENV=development" >> $GITHUB_OUTPUT
            echo "API_URL=https://api-dev.stepfun.com" >> $GITHUB_OUTPUT
          fi
      
      - name: Build for ${{ steps.env.outputs.ENV }}
        run: pnpm run build
        env:
          VITE_API_URL: ${{ steps.env.outputs.API_URL }}
          VITE_ENV: ${{ steps.env.outputs.ENV }}
      
      - name: Deploy
        run: vercel deploy --prod=${{ steps.env.outputs.ENV == 'production' }}
3️⃣ PR 预览部署（Preview Deploy）
# .github/workflows/pr-preview.yml
name: PR Preview Deploy

on:
  pull_request:
    branches: [main]

jobs:
  preview:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Deploy Preview
        uses: amondnet/vercel-action@v20
        id: deploy
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}
      
      - name: Comment Preview URL
        uses: actions/github-script@v6
        with:
          script: |
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.name,
              body: '🚀 Preview deployed: ${{ steps.deploy.outputs.preview-url }}'
            })

🎤 面试高频 QA

Q1: CI/CD 的好处是什么？

✅ 核心价值：

  1. 提升效率：自动化构建部署，从手动 30 分钟 → 自动 5 分钟
  2. 降低风险：每次提交都测试，及早发现问题
  3. 快速反馈：代码问题几分钟内就能发现
  4. 频繁发布：每天可以发布多次，而不是每周一次
  5. 一致性：所有环境使用相同的构建流程
  6. 可追溯：每次部署都有记录，方便回滚
Q2: GitHub Actions 的核心概念？
  • Workflow：工作流，定义在 .github/workflows/*.yml
  • Job：任务，一个 workflow 包含多个 job
  • Step：步骤，一个 job 包含多个 step
  • Action：可复用的步骤（如 actions/checkout@v3）
  • Runner：执行环境（ubuntu-latest/windows/macos）
  • Event：触发条件（push/pull_request/schedule）
Q3: 如何优化 CI/CD 速度？

⚡ 优化策略：

  1. 缓存依赖：缓存 node_modules（actions/cache）
  2. 并行执行：多个 job 并行运行
  3. 增量构建：只构建变化的部分
  4. Docker 镜像：使用预构建镜像
  5. 矩阵策略：多版本并行测试
  6. 按需触发：只在必要时运行（paths 过滤）
Q4: 如何管理环境变量和密钥？
# 1. GitHub Secrets（推荐）
# Settings -> Secrets and variables -> Actions
# 添加 secret: VERCEL_TOKEN

# 4. 环境变量文件
# .env.production（不提交）
# .env.example（提交，作为模板）

# ⚠️ 注意：
# • 永远不要在代码中硬编码密钥
# • 不要在日志中打印密钥
# • 使用 GitHub Secrets 管理敏感信息
Q5: 部署失败如何快速回滚？

🔄 回滚策略：

# 1. Vercel 快速回滚
vercel rollback

# 2. Git 回滚
git revert <commit-hash>
git push origin main

# 3. 蓝绿部署（Zero Downtime）
# • 部署新版本到新环境
# • 测试通过后切换流量
# • 出问题立即切回旧环境

# 4. 金丝雀发布（Canary）
# • 5% 流量到新版本
# • 观察指标正常后逐步放量
# • 10% -> 50% -> 100%

# 5. 自动回滚
# • 监控关键指标（错误率/响应时间）
# • 指标异常自动回滚

✅ CI/CD 最佳实践

✅ 应该做的

  • • 每次提交都触发 CI
  • • 测试失败阻止合并
  • • 自动化部署到测试环境
  • • 手动确认后部署到生产
  • • 使用 Secrets 管理密钥
  • • 缓存依赖提升速度
  • • 部署成功后发送通知
  • • 保留部署历史记录

❌ 不应该做的

  • • 跳过测试直接部署
  • • 在代码中硬编码密钥
  • • 手动部署到生产环境
  • • 没有回滚机制
  • • 忽略 CI 失败
  • • 测试和部署串行执行
  • • 没有环境隔离
  • • 不监控部署状态

⚠️ 常见陷阱

❌ 陷阱 1：密钥泄露

// ❌ 错误：硬编码密钥
const API_KEY = 'sk-123456789';

// ❌ 错误：提交 .env 文件
git add .env

// ✅ 正确：使用 GitHub Secrets
env:
  API_KEY: ${{ secrets.API_KEY }}

// ✅ 正确：.gitignore 忽略
.env
.env.local
.env.production

❌ 陷阱 2：没有缓存导致构建慢

// ❌ 错误：每次都重新安装依赖
- run: npm install  # 5 分钟

// ✅ 正确：缓存 node_modules
- uses: actions/cache@v3
  with:
    path: node_modules
    key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
- run: npm install  # 10 秒

❌ 陷阱 3：没有回滚机制

// ❌ 错误：部署后无法回滚
deploy:
  - run: npm run deploy
  # 出问题了怎么办？

// ✅ 正确：支持快速回滚
deploy:
  - run: npm run deploy
  - name: Rollback on failure
    if: failure()
    run: vercel rollback
