停止生成功能

使用 AbortController 实现 AI 流式生成的优雅中断

💡 核心代码实现

// 1. 创建 AbortController
const abortController = new AbortController();
const { signal } = abortController;

// 2. 传递 signal 给 fetch
const response = await fetch('/api/generate', {
  method: 'POST',
  signal // 关键！
});

// 3. 读取流式响应
const reader = response.body.getReader();
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  // 处理数据...
}

// 4. 停止按钮调用
function stopGeneration() {
  abortController.abort(); // 取消请求
}

// 5. 捕获取消错误
try {
  // ... fetch 逻辑
} catch (error) {
  if (error.name === 'AbortError') {
    console.log('用户取消了请求');
  }
}

🎯 技术要点总结

1️⃣
创建 AbortController

每个请求创建一个新实例，获取 signal 对象

2️⃣
传递 signal

将 signal 作为 fetch 的选项传递

3️⃣
调用 abort()

用户点击停止按钮时，调用 abortController.abort()

4️⃣
处理 AbortError

catch 块中判断 error.name === 'AbortError'

5️⃣
检查 signal.aborted

在长时间操作中定期检查是否已取消

⚠️ 实际项目注意事项

  • • 清理资源：abort 后要清理定时器、事件监听等
  • • UI 反馈：给用户明确的停止提示
  • • 状态管理：正确更新 loading 状态，避免 UI 卡住
  • • 后端配合：后端也要支持连接关闭时停止生成
  • • 重复请求：停止后再次生成，要创建新的 AbortController

🎤 面试场景模拟

👔
面试官：你们项目中如何实现 AI 生成的停止功能？
✅ 好的回答：

我们使用 AbortController 实现，主要分 4 步：

  1. 创建实例：每次发起生成请求时，创建新的 AbortController
  2. 传递 signal：将 signal 传递给 fetch 请求
  3. 用户停止：点击停止按钮时调用 abort() 方法
  4. 错误处理：catch 中判断 AbortError，更新 UI 状态

这样既能优雅地取消请求，又能节省 API 成本。

❌ 差的回答：
"就是加个停止按钮，点了就不显示了。"（没有取消请求，浪费资源）
👔
面试官：如果用户快速点击"生成"和"停止"，会有什么问题？
✅ 核心要点：

问题：可能出现多个并发请求，状态混乱

解决方案：

let currentController = null;

function startGeneration() {
  // 1. 先取消之前的请求
  if (currentController) {
    currentController.abort();
  }
  
  // 2. 创建新的 Controller
  currentController = new AbortController();
  
  // 3. 发起请求
  fetch('/api/generate', { 
    signal: currentController.signal 
  });
}

function stopGeneration() {
  if (currentController) {
    currentController.abort();
    currentController = null; // 清理引用
  }
}

关键：用变量保存当前 Controller，新请求前先取消旧请求

👔
面试官：停止生成后，后端还在计算怎么办？
✅ 好的回答：

前端层面：

  • AbortController 会关闭 HTTP 连接
  • SSE 连接中断，后端能检测到

后端层面：

  • 监听客户端连接状态（如 Node.js 的 req.on('close')）
  • 检测到断开后，停止 AI 生成任务
  • 释放资源，取消 API 调用
// Node.js 后端示例
app.post('/api/generate', (req, res) => {
  let aborted = false;
  
  req.on('close', () => {
    aborted = true; // 客户端断开
    console.log('Client disconnected');
  });
  
  async function* generate() {
    for (let chunk of aiStream) {
      if (aborted) break; // 停止生成
      yield chunk;
    }
  }
});

💡 关键：前后端配合，完整实现取消逻辑

❓ 面试高频 QA

Q1: AbortController 和 setTimeout 取消有什么区别？

AbortController

  • 标准浏览器 API
  • 可以取消 fetch、事件监听
  • 支持多个操作共享 signal
  • 有标准的错误处理

clearTimeout

  • 只能取消定时器
  • 需要保存 timerId
  • 不能取消网络请求
  • 无错误对象

💡 推荐：网络请求用 AbortController，定时器用 clearTimeout

Q2: 一个 signal 可以用于多个请求吗？

可以！这是 signal 的强大之处

const controller = new AbortController();
const { signal } = controller;

// 多个请求共享同一个 signal
Promise.all([
  fetch('/api/user', { signal }),
  fetch('/api/posts', { signal }),
  fetch('/api/comments', { signal })
]);

// 一次取消，所有请求都停止
controller.abort();

应用场景：

  • 页面切换时取消所有未完成的请求
  • 组件卸载时清理所有异步操作
  • 搜索功能，新搜索时取消所有旧请求
Q3: React 中如何配合 useEffect 使用？

在 useEffect cleanup 中调用 abort：

useEffect(() => {
  const controller = new AbortController();
  
  async function fetchData() {
    try {
      const res = await fetch('/api/data', {
        signal: controller.signal
      });
      const data = await res.json();
      setData(data);
    } catch (error) {
      if (error.name !== 'AbortError') {
        console.error(error);
      }
    }
  }
  
  fetchData();
  
  // cleanup: 组件卸载时取消请求
  return () => {
    controller.abort();
  };
}, []);

💡 好处：避免内存泄漏，防止已卸载组件更新状态

Q4: 阶跃星辰的产品中，停止生成功能还需要考虑什么？

完整的用户体验方案：

1. UI 反馈

  • 停止按钮明显，易于点击
  • 停止后显示"已停止"提示
  • 已生成的内容保留

2. 成本统计

  • 记录实际生成的 Token 数
  • 停止时计算消耗
  • 给用户展示节省的成本

3. 会话管理

  • 停止后的内容算作一轮对话
  • 支持在停止的位置继续生成
  • 保存停止时的上下文

4. 错误处理

  • 区分用户主动停止和网络错误
  • 停止失败时的降级方案
  • 连接断开的重连策略

🔥 可能的追问

追问 1：如果后端不支持中断，前端如何处理？

→ 前端停止显示，后台静默继续，但不消耗用户注意力

追问 2：停止后能否恢复继续生成？

→ 需要后端支持，传递之前的 context 和停止位置

追问 3：WebSocket 连接如何实现停止？

→ 发送停止消息给后端，或直接关闭 WebSocket 连接

追问 4：停止功能如何做埋点统计？

→ 记录停止时间、已生成字数、用户停止原因等

追问 5：移动端如何优化停止按钮的可用性？

→ 悬浮按钮、手势滑动停止、震动反馈
