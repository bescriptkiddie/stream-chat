对话历史优化

虚拟滚动 + 分页加载 + LRU 缓存 - AI 聊天性能优化

📚 核心优化策略

虚拟滚动

  • • 问题：1万条消息 = 1万个 DOM 节点
  • • 解决：只渲染可见区域（~20 个节点）
  • • 效果：性能提升 500x+
  • • 关键：计算可见范围 + transform 偏移

分页加载

  • • 问题：一次加载全部历史记录
  • • 解决：按需加载，滚动到底部加载更多
  • • 效果：首屏加载快 10x+
  • • 关键：Intersection Observer + 分页 API

LRU 缓存

  • • 问题：重复访问的消息重复加载
  • • 解决：最近访问的保留，最久的淘汰
  • • 效果：缓存命中率 80%+
  • • 关键：Map + 双向链表（或 Map）

🚀 虚拟滚动演示

• 当前消息数：0 条

• 实际渲染：~20 个 DOM 节点（可见区域 + 缓冲区）

• 性能提升：0x

• 滚动尝试：快速滚动，观察流畅度

// 虚拟滚动核心代码
// 1. 计算可见范围
const visibleCount = Math.ceil(containerHeight / itemHeight);
const startIndex = Math.floor(scrollTop / itemHeight) - bufferSize;
const endIndex = startIndex + visibleCount + bufferSize * 2;

// 2. 只渲染可见消息
const visibleMessages = messages.slice(startIndex, endIndex);

// 3. 使用 transform 实现滚动
const offsetY = startIndex * itemHeight;
<div style={{ transform: `translateY(${offsetY}px)` }}>
  {visibleMessages.map(msg => <MessageItem />)}
</div>

面试官：虚拟滚动的原理是什么？有什么坑？

✅ 原理与注意事项：

原理：

// 1. 计算可见区域
const startIndex = Math.floor(scrollTop / itemHeight);
const endIndex = startIndex + visibleCount;

// 2. 只渲染可见项
const visibleItems = items.slice(startIndex, endIndex);

// 3. 使用 transform 偏移
<div style={{ 
  height: totalHeight,  // 保持总高度
  transform: `translateY(${startIndex * itemHeight}px)`
}}>
  {visibleItems.map(item => <Item />)}
</div>

⚠️ 常见坑：

  • 动态高度：消息高度不固定，需要动态计算
  • 白屏问题：快速滚动时加载不及时，需缓冲区
  • 定位问题：跳转到指定消息需计算累计高度
  • 滚动抖动：新消息加载导致滚动位置变化
面试官：LRU 缓存的实现原理？

✅ 两种实现方式：

方法 1: Map（简单）

class LRUCache {
  constructor(capacity) {
    this.cache = new Map();
    this.capacity = capacity;
  }

  get(key) {
    if (!this.cache.has(key)) return null;
    // 删除后重新插入 = 移到末尾
    const val = this.cache.get(key);
    this.cache.delete(key);
    this.cache.set(key, val);
    return val;
  }

  set(key, val) {
    if (this.cache.has(key)) {
      this.cache.delete(key);
    }
    this.cache.set(key, val);
    
    // 超容量删除第一个
    if (this.cache.size > this.capacity) {
      const first = this.cache.keys().next().value;
      this.cache.delete(first);
    }
  }
}

方法 2: 双向链表 + HashMap（最优）

  • HashMap: 快速查找 O(1)
  • 双向链表: 快速移动节点 O(1)
  • 头部 = 最近使用
  • 尾部 = 最久未使用（淘汰）

💡 时间复杂度：get/set 都是 O(1)

→ 测量每项真实高度，维护高度数组，累加计算位置

追问 2：如何实现平滑滚动到指定消息？

→ scrollTo + smooth behavior，或 requestAnimationFrame 自定义动画

追问 3：新消息到达时如何保持滚动位置？

→ 判断是否在底部，是则滚动到底部，否则保持原位置

追问 4：缓存失效策略是什么？

→ LRU 自动淘汰 + 定时清理 + 版本号控制

追问 5：移动端如何优化？

→ 更小的缓冲区 + 懒加载图片 + 简化样式
