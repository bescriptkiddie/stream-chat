📚 核心技术

IndexedDB

  • • 浏览器端数据库
  • • 支持大量数据存储
  • • 异步 API
  • • 离线可用

数据结构

  • • sessions: 会话列表
  • • messages: 消息记录
  • • 索引: 提升查询性能
  • • 关联: sessionId 外键

应用场景

  • • ChatGPT 式多对话
  • • 离线消息缓存
  • • 历史记录持久化

// 1. 初始化数据库
async init() {
  return new Promise((resolve, reject) => {
    const request = indexedDB.open(this.dbName, this.version);

    request.onsuccess = () => {
      this.db = request.result;
      resolve(this.db);
    };

    // 创建表结构
    request.onupgradeneeded = (event) => {
      const db = event.target.result;
      
      // 会话表
      const sessionStore = db.createObjectStore('sessions', { 
        keyPath: 'id' 
      });
      sessionStore.createIndex('updatedAt', 'updatedAt');

      // 消息表
      const messageStore = db.createObjectStore('messages', { 
        keyPath: 'id' 
      });
      messageStore.createIndex('sessionId', 'sessionId');
    };
  });
}

// 2. 添加数据
async createSession(title) {
  const session = {
    id: `session_${Date.now()}`,
    title,
    createdAt: Date.now(),
    updatedAt: Date.now()
  };

  const transaction = this.db.transaction(['sessions'], 'readwrite');
  await transaction.objectStore('sessions').add(session);
  return session;
}

// 3. 查询数据（使用索引）
async getAllSessions() {
  return new Promise((resolve) => {
    const transaction = this.db.transaction(['sessions'], 'readonly');
    const store = transaction.objectStore('sessions');
    const index = store.index('updatedAt');
    const request = index.openCursor(null, 'prev'); // 倒序

    const sessions = [];
    request.onsuccess = (event) => {
      const cursor = event.target.result;
      if (cursor) {
        sessions.push(cursor.value);
        cursor.continue();
      } else {
        resolve(sessions);
      }
    };
  });
}

// 4. 删除数据（级联删除）
async deleteSession(sessionId) {
  const transaction = this.db.transaction(
    ['sessions', 'messages'], 
    'readwrite'
  );
  
  // 删除会话
  await transaction.objectStore('sessions').delete(sessionId);

  // 删除相关消息
  const messageStore = transaction.objectStore('messages');
  const index = messageStore.index('sessionId');
  const request = index.openCursor(IDBKeyRange.only(sessionId));

  request.onsuccess = (event) => {
    const cursor = event.target.result;
    if (cursor) {
      cursor.delete();
      cursor.continue();
    }
  };
}

🎤 面试场景模拟

👔
面试官：为什么选择 IndexedDB 而不是 LocalStorage？
✅ 好的回答：

LocalStorage

  • 同步 API，阻塞主线程
  • 只能存储字符串（5-10MB）
  • 无索引，查询慢
  • 适合：简单配置、token

IndexedDB

  • 异步 API，不阻塞
  • 存储任意类型（数百 MB）
  • 支持索引，查询快
  • 适合：大量数据、复杂查询

💡 AI 对话场景：需要存储大量消息历史，支持多会话查询，IndexedDB 是最佳选择

👔
面试官：IndexedDB 的事务机制是什么？
✅ 好的回答：

IndexedDB 所有操作都必须在事务中进行：

  1. readonly：只读事务，多个可并发
  2. readwrite：读写事务，同一 store 会串行
  3. versionchange：升级数据库结构时使用
// 创建事务
const transaction = db.transaction(['sessions'], 'readwrite');
const store = transaction.objectStore('sessions');

// 操作数据
store.add(data);
store.get(id);

// 事务自动提交，无需手动 commit

💡 优势：保证数据一致性，操作要么全成功，要么全失败

面试官：如何实现多会话的搜索功能？
✅ 好的回答：

方案 1：客户端全文搜索

async search(keyword) {
  const sessions = await this.getAllSessions();
  const results = [];

  for (const session of sessions) {
    const messages = await this.getMessages(session.id);
    const matchedMessages = messages.filter(msg =>
      msg.content.includes(keyword)
    );
    
    if (matchedMessages.length > 0) {
      results.push({ session, messages: matchedMessages });
    }
  }

  return results;
}

Q3: 如何处理数据迁移和版本升级？

onupgradeneeded 事件中处理：

request.onupgradeneeded = (event) => {
  const db = event.target.result;
  const oldVersion = event.oldVersion;

  // v1 → v2: 添加新字段
  if (oldVersion < 2) {
    const transaction = event.target.transaction;
    const store = transaction.objectStore('sessions');
    
    // 遍历所有记录，添加新字段
    store.openCursor().onsuccess = (e) => {
      const cursor = e.target.result;
      if (cursor) {
        const data = cursor.value;
        data.newField = 'default';
        cursor.update(data);
        cursor.continue();
      }
    };
  }

  // v2 → v3: 创建新表
  if (oldVersion < 3) {
    db.createObjectStore('newStore', { keyPath: 'id' });
  }
};
Q4: IndexedDB 和后端数据如何同步？

常见同步策略：

策略 1: 本地优先（Offline First）

  • 操作先写入 IndexedDB
  • 后台异步同步到服务器
  • 记录同步状态（pending/synced）
  • 适用：离线应用、PWA

策略 2: 服务端优先（Server First）

  • 操作先发送到服务器
  • 成功后更新 IndexedDB
  • IndexedDB 作为缓存
  • 适用：实时协作、多端同步

🔥 可能的追问

追问 1：IndexedDB 是否支持跨域访问？

→ 不支持，每个源（origin）有独立的数据库

追问 2：如何清理过期数据？

→ 定期扫描 createdAt，删除超过 N 天的记录

追问 3：IndexedDB 性能如何优化？

→ 使用索引、批量操作、避免大事务、合理分表

追问 4：用户清除浏览器数据会丢失吗？

→ 会丢失，需要定期同步到服务器备份
