useDebounce Hook

防抖 Hook 实现 - 常用于搜索框输入优化

实时值（立即更新）
...
防抖值（延迟 500ms）
...

模拟 API 调用日志（仅防抖后触发）

等待输入...

💡 核心原理

  • • 使用 setTimeout 延迟更新状态
  • • useEffect cleanup 函数清除上一次的定时器
  • • 避免频繁触发 API 请求，节省资源
  • • 典型应用：搜索框、窗口 resize 事件

📝 核心代码实现

function useDebounce(value, delay) {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    // 设置定时器
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    // cleanup: 清除上一次的定时器
    return () => {
      clearTimeout(timer);
    };
  }, [value, delay]);

  return debouncedValue;
}

// 使用示例
const [searchTerm, setSearchTerm] = useState('');
const debouncedSearchTerm = useDebounce(searchTerm, 500);

useEffect(() => {
  if (debouncedSearchTerm) {
    // 只有当用户停止输入 500ms 后才调用 API
    searchAPI(debouncedSearchTerm);
  }
}, [debouncedSearchTerm]);

🎤 面试场景模拟

👔
面试官：请实现一个 useDebounce Hook
✅ 好的回答：

useDebounce 主要用于延迟更新值，核心实现：

  1. useState：保存防抖后的值
  2. useEffect：监听原始值变化
  3. setTimeout：延迟更新
  4. cleanup：清除旧定时器

典型应用是搜索框，用户停止输入后才发起请求。

👔
面试官：防抖和节流有什么区别？
✅ 核心区别：

防抖 (Debounce)

  • • 连续触发只执行最后一次
  • • 等待用户停止操作
  • • 场景：搜索框、表单验证
  • • 节省：减少请求次数

节流 (Throttle)

  • • 固定时间内只执行一次
  • • 持续执行但控制频率
  • • 场景：滚动、resize
  • • 节省：控制执行频率

💡 记忆技巧：防抖等最后一次，节流控制频率

👔
面试官：如果需要立即执行一次怎么办？
✅ 好的回答：

可以添加 immediate 参数：

function useDebounce(value, delay, immediate = false) {
  const [debouncedValue, setDebouncedValue] = useState(value);
  const [isFirstRun, setIsFirstRun] = useState(true);

  useEffect(() => {
    // 首次立即执行
    if (immediate && isFirstRun) {
      setDebouncedValue(value);
      setIsFirstRun(false);
      return;
    }

    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    return () => clearTimeout(timer);
  }, [value, delay, immediate, isFirstRun]);

  return debouncedValue;
}

❓ 面试高频 QA

Q1: 为什么要在 useEffect cleanup 中清除定时器？

不清除会导致：

  • 旧定时器仍会执行，造成多次更新
  • 内存泄漏
  • 状态更新不符合预期

示例：

用户输入 "abc"，每个字母触发一次 useEffect，如果不清除，会有 3 个定时器，最终触发 3 次更新。

Q2: useDebounce 会造成性能问题吗？

不会，反而优化性能：

  • 减少不必要的计算和渲染
  • 减少 API 请求次数
  • setTimeout 和 clearTimeout 性能开销很小

💡 优化建议：对于大量实例，可以用 useMemo 缓存 Hook

Q3: 搜索框应该用多长的延迟时间？

推荐配置：

  • 300-500ms：搜索框（常用）
  • 200-300ms：自动保存
  • 500-1000ms：输入验证
  • 100-200ms：实时反馈

根据用户体验和服务器压力平衡选择

Q4: 如何测试 useDebounce？
import { renderHook, act } from '@testing-library/react';
import { useDebounce } from './useDebounce';

test('should debounce value', async () => {
  jest.useFakeTimers();
  
  const { result, rerender } = renderHook(
    ({ value, delay }) => useDebounce(value, delay),
    { initialProps: { value: 'initial', delay: 500 } }
  );

  expect(result.current).toBe('initial');

  // 快速改变值
  rerender({ value: 'a', delay: 500 });
  rerender({ value: 'ab', delay: 500 });
  rerender({ value: 'abc', delay: 500 });

  // 500ms 前不应更新
  act(() => {
    jest.advanceTimersByTime(300);
  });
  expect(result.current).toBe('initial');

  // 500ms 后应更新为最后的值
  act(() => {
    jest.advanceTimersByTime(200);
  });
  expect(result.current).toBe('abc');

  jest.useRealTimers();
});

🔥 可能的追问

追问 1：如果组件卸载时还有未完成的定时器怎么办？

→ useEffect cleanup 会自动清除，不会导致内存泄漏

追问 2：能用 useMemo 实现 useDebounce 吗？

→ 不能，useMemo 是同步的，无法处理异步延迟

追问 3：在 AI 产品中如何应用？

→ 用户输入 Prompt 时防抖，减少 Token 计算次数

追问 4：如何取消正在进行的防抖？

→ 暴露 cancel 方法，或者将 delay 设为 0
