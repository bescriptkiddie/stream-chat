🔥 进阶挑战

挑战 1: 实现 DeepPartial（深度可选）

要求：

将对象及其所有嵌套对象的属性都变为可选

答案：

type DeepPartial<T> = {
  [P in keyof T]?: T[P] extends object 
    ? DeepPartial<T[P]> 
    : T[P];
};

// 使用
interface Config {
  app: {
    name: string;
    version: string;
    settings: {
      theme: string;
    };
  };
}

type PartialConfig = DeepPartial<Config>;
// app 可选, app.name 可选, app.settings.theme 可选
挑战 2: 实现 PartialPick（部分属性可选）

要求：

选中的属性变为可选，其他属性保持不变

答案：

type PartialPick<T, K extends keyof T> = 
  Partial<Pick<T, K>> & Omit<T, K>;

// 使用
interface User {
  id: number;
  name: string;
  email: string;
  age: number;
}

type UserPartialName = PartialPick<User, 'name' | 'email'>;
// {
//   id: number;        // 必填
//   name?: string;     // 可选
//   email?: string;    // 可选
//   age: number;       // 必填
// }
挑战 3: 实现 GetRequired（获取必填属性）

要求：

从对象中提取所有必填属性

答案：

type GetRequired<T> = {
  [P in keyof T as T[P] extends Required<T>[P] ? P : never]: T[P];
};

// 使用
interface User {
  id: number;
  name: string;
  email?: string;
  age?: number;
}

type UserRequired = GetRequired<User>;
// {
//   id: number;
//   name: string;
// }

❓ 面试高频 QA

Q1: 映射类型中的 ? 和 -? 有什么区别？

? 添加可选

type Partial<T> = {
  [P in keyof T]?: T[P];
};
// 将属性变为可选

-? 移除可选

type Required<T> = {
  [P in keyof T]-?: T[P];
};
// 移除可选，变为必填

💡 同理，readonly 和 -readonly 分别添加和移除只读

Q2: infer 是如何工作的？

infer 用于在条件类型中推断类型：

// 1. 推断函数返回值
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
//                                                 ^^^^^^^ 推断这里的类型

// 2. 推断函数参数
type Parameters<T> = T extends (...args: infer P) => any ? P : never;
//                                        ^^^^^^^ 推断这里的类型

// 3. 推断 Promise 类型
type Awaited<T> = T extends Promise<infer U> ? U : T;
//                                  ^^^^^^^ 推断这里的类型

// 4. 推断数组元素类型
type ArrayElement<T> = T extends (infer U)[] ? U : never;
//                                 ^^^^^^^ 推断这里的类型

💡 关键：infer 声明一个类型变量，TS 会自动推断其类型

Q3: 为什么需要 extends keyof T 约束？

类型安全保证：

❌ 没有约束

type Pick<T, K> = {
  [P in K]: T[P]; 
  // ❌ 错误：K 可能不是 T 的键
};

type Result = Pick<User, 'xyz'>;
// 编译通过，但 'xyz' 不存在

✅ 有约束

type Pick<T, K extends keyof T> = {
  [P in K]: T[P];
  // ✅ K 必须是 T 的键
};

type Result = Pick<User, 'xyz'>;
// ❌ 编译错误：'xyz' 不是 User 的键
Q4: 实际项目中如何应用这些类型体操？

阶跃星辰 AI 产品的实际应用：

1. API 请求参数

interface CreateSessionDto {
  title: string;
  model: string;
  temperature?: number;
  maxTokens?: number;
}

// 更新时只需部分字段
type UpdateSessionDto = Partial<CreateSessionDto>;

// 响应只返回部分字段
type SessionResponse = Pick<Session, 'id' | 'title' | 'createdAt'>;

2. 表单状态管理

interface FormData {
  username: string;
  password: string;
  rememberMe: boolean;
}

// 表单错误状态（所有字段可选）
type FormErrors = Partial<Record<keyof FormData, string>>;

// 表单验证规则（部分字段必填）
type FormRules = PartialPick<FormData, 'rememberMe'>;

3. Redux State

interface AppState {
  user: User;
  sessions: Session[];
  config: Config;
}

// State 只读
type ReadonlyState = DeepReadonly<AppState>;

// Action payload 类型
type UpdateUserAction = {
  type: 'UPDATE_USER';
  payload: Partial<User>;
};

🔥 可能的追问

追问 1：类型体操会影响运行时性能吗？

→ 不会，TypeScript 编译后会擦除所有类型信息

追问 2：如何调试复杂的类型？

→ 使用 type-fest 库 + TS Playground + 类型注释

追问 3：递归类型有深度限制吗？

→ 有，TS 4.5+ 支持尾递归优化，深度限制约 1000 层

追问 4：类型体操和 JavaScript 运行时有什么关系？

→ 完全无关，类型是编译时概念，不存在于运行时
